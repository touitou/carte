0) Présentation du projet (version client)

À quoi sert ce projet ?

Cette solution aide à identifier rapidement des opportunités foncières et immobilières à partir de données publiques et d’enrichissements métiers.

  • repérer des parcelles potentiellement intéressantes,
  • visualiser ces opportunités sur une carte interactive,
  • comprendre le contexte (prix, surface, permis, usages, contraintes urbanistiques),
  • prioriser les dossiers grâce à un score.

Pour quels usages ?

  • prospection foncière,
  • qualification d’un secteur avant acquisition,
  • aide à la décision pour développeurs, investisseurs, aménageurs,
  • préparation d’échanges avec partenaires, collectivités et équipes internes.

D’où viennent les données ? (explication simple)

  • DVF : historique des transactions immobilières (prix, dates, surfaces),
  • BDNB : informations bâtiment/parcelle (géométrie, usages, adresses...),
  • Sitadel / autorisations d’urbanisme : signaux de permis et dynamiques de transformation,
  • PLU (Géoportail de l’urbanisme / IGN) : zonage et documents de référence,
  • et, selon options, des compléments pour mieux qualifier occupants/propriétaires.

Quelle valeur pour un client ?

  • gain de temps sur la recherche,
  • vision cartographique immédiate,
  • priorisation objective via des critères paramétrables,
  • meilleure préparation des analyses terrain et décisions.

Quels types de potentiels cela permet d’ouvrir ?

1) Potentiel foncier

  • Parcelles sous-valorisées au regard des références locales.
  • Surfaces de terrain importantes avec faible niveau d’occupation bâtie.
  • Opportunités de recomposition parcellaire ou d’assemblage.

2) Potentiel de densification / transformation

  • Sites avec marge de création de surface (selon contexte urbanistique).
  • Parcelles présentant des signaux de transformation via les permis.
  • Bâtiments ou emprises pouvant faire l’objet d’un repositionnement.

3) Potentiel de requalification d’actifs

  • Actifs anciens à revaloriser (année de construction, usage, état énergétique).
  • Ciblage de poches de valeur via croisement prix/surfaces/usages.
  • Hiérarchisation des actifs à arbitrer, rénover ou transformer.

4) Potentiel commercial et pipeline

  • Constitution d’un pipeline qualifié de cibles.
  • Priorisation des actions de prospection selon score et critères métiers.
  • Préparation de rendez-vous et argumentaires avec données objectivées.

5) Potentiel partenarial et territorial

  • Dialogue renforcé avec collectivités et partenaires locaux.
  • Identification de secteurs cohérents avec une stratégie d’implantation.
  • Appui à la planification d’actions par zone géographique.

6) Potentiel ESG / transition

  • Repérage d’actifs à enjeu énergétique (DPE).
  • Orientation vers des scénarios de rénovation et amélioration de performance.
  • Intégration des contraintes urbanistiques dans une stratégie durable.

En résumé : la plateforme aide à construire une stratégie d’opportunités multi-axes (foncier, transformation, commercial, territorial, ESG).

Important à retenir

  • L’outil est un assistant d’analyse : il accélère le tri et la compréhension.
  • Les résultats doivent être confirmés par expertise métier et vérifications locales.

1) Périmètre technique

  • Écran de recherche : run_gradio_bdnb.py (build_demo())
  • Pipeline calcul/enrichissement : immo_bdnb.py (run_bdnb_opportunites)
  • Carte et popup : immo_folium.py (build_map_html)
  • Table HTML : immo_folium.py (build_table_html)

2) Sources de données

2.1 Source principale BDNB (DuckDB)

  • Fichier : bdnb_millesime_2025-07-a.duckdb
  • Tables principales : batiment_groupe_dvf_open_representatif, batiment_groupe, parcelle, adresse, proprietaire, sitadel, batiment_groupe_urbanisme, batiment_groupe_dpe_*...

2.2 Source DVF CSV (scope complémentaire)

  • Paramètre UI : DVF CSV glob
  • Défaut : downloads/csv/National/merged/dvf_plus_d*.csv

2.3 Source permis CSV (Sitadel externe)

  • Paramètre UI : Permis CSV path
  • Défaut : data/Liste-des-autorisations-durbanisme-creant-des-locaux-non-residentiels.2025-12.csv

2.4 API IGN GPU (optionnelle)

  • Option UI : PLU GPU (API IGN, réseau, cache)
  • API : https://apicarto.ign.fr/api/gpu/zone-urba
  • Cache local : cache_plu_gpu.parquet

2.5 Cache SIRENE (optionnel)

  • Géré via sirene_cache.py / cache_enrich.duckdb

3.6 Sorties affichées

  • Liens des fichiers HTML et bloc publication GitHub Pages.

4) Champs affichés dans la carte (popup Folium)

4.1 Fiche

Transaction, parcelle, cadastre, commune, adresse, type de bien, date mutation, valeur foncière, surfaces, ratio bâti/parcelle, prix/m², médiane commune, écart, score, année construction, niveaux, usages.

4.2 Propriétaires

Liste propriétaires, SIREN valides, autres IDs, liens sociétés (Annuaire, Pappers, Societe.com).

4.3 Permis & occupants

Historique permis, occupants SIRENE (si disponibles), demandeurs Sitadel.

4.4 Énergie (DPE)

DPE logement et tertiaire (classe, conso, GES).

4.5 Urbanisme

Monument historique, dénomination, distance.

4.6 PLU

Zone PLU (GPU/BDNB), partition, liens Géoportail, règlement et autres documents.

5) Champs affichés dans la table HTML associée à la carte

La table reprend les colonnes disponibles parmi la sélection prioritaire du code (cols_pref) :

score, date_mutation, valeur_fonciere, surface_terrain_mutee, parcelle_area_m2, batiment_area_m2, bati_ratio, prix_m2_terrain, prix_m2_ref_commune, delta_ref, libelle_commune_insee, libelle_adresse, annee_construction, usage_niveau_1_txt, usage_principal_bdnb_open, dpe_logement_classe, dpe_logement_conso_ep_m2, dpe_logement_ges_kgco2_m2, liste_proprietaires, nb_siren_valides, nb_ids_autres, nb_permis, permis_last_date, permis_last_numero, permis_last_nature, permis_last_statut, permis_last_s_hab_creee, permis_last_s_loc_creee, nb_demandeurs_permis, liste_demandeurs_permis, plu_zone_code, plu_zone_type, plu_doc_partition, zone_plu_bati_patrimonial.

6) Logique d’assemblage (résumé)

  1. Filtrage principal transactions (BDNB + critères écran)
  2. Extension optionnelle scope parcelles BDNB
  3. Extension optionnelle scope DVF CSV
  4. Enrichissements (adresse, propriétaires, permis, DPE, urbanisme)
  5. Calcul du score
  6. Construction géométrie affichée (centroid/parcelle/batiment)
  7. Enrichissement optionnel PLU GPU
  8. Rendu carte + popup + table HTML

7) Remarques importantes

  • Certains champs n’apparaissent que si l’enrichissement correspondant est activé (ex: PLU GPU).
  • En cas de données manquantes, le popup affiche « Non disponible » ou des cellules vides.
  • La carte finale filtre les lignes sans géométrie exploitable (geo).
